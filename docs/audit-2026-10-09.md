# Full audit, 9 October 2026

Scope: the whole repository and the live game, seen as a game developer, a gamer, a distributor (store publisher) and
an everyday user. Each item says what is wrong or missing, why it matters and how big the fix is.
**Checked** means I verified it in the code or in the running game today; **Judged** means it comes from experience
with similar games and should be confirmed before acting.

Priority: **P0** do before real users or a store build · **P1** soon · **P2** later.
Size: S under an hour · M a session · L several sessions.

## 1. Game developer

| Pri | Item | Why | Size |
|---|---|---|---|
| P0 | **No rules or protocol version.** Replay links, saved matches and multiplayer all replay moves through the engine, and nothing records which rules they were made with. *Checked:* `SavedGame.v` and `hello` carry no rules version; today's change (two takes in a Double move earn Armor) already alters how old move lists play out. A host and a guest on different app versions would silently desync (no checksum either). | Old replay links and saves can break or show a different match; store updates roll out unevenly, so mixed versions in one room are certain. | M: `RULES_VERSION` in the engine, stored in saves, replay codes and `hello`; refuse or warn on mismatch; a state hash sent every few moves to detect desync. |
| P0 | **No error boundary.** *Checked:* no `ErrorBoundary`, no `onerror` handler. One render error white-screens the app and the broken save reloads into the same crash. | The worst first impression; hard to diagnose without reports. | S |
| P1 | `controller.ts` is 1,009 lines and mixes match flow, effects, timers, saves, net and replay. | Every new feature touches it; bugs hide in it. | L: split into flow, effects (trails, bursts, toasts, slashes), persistence, net. |
| P1 | **Tests cover only the engine** (44 tests). No test opens the app. | UI regressions (like the clipped popups) reach players. | M: a headless smoke test in CI that visits every route in two languages and fails on console errors; an engine test for each bonus rule. |
| P1 | No linter or formatter; the engine is plain JS with hand-written `.d.ts` files that can drift from the code. | Silent mismatches between types and behavior. | M: ESLint + `// @ts-check` on the engine, or port it to TypeScript. |
| P1 | Bundle is 650 kB (210 kB gzipped); all six dictionaries (250 kB of source) and all puzzles are in it. | Slower first load on mobile data. | S: load only the chosen language and lazy-load puzzles. |
| P2 | `arena/index.html` duplicates the rules text and the bot code path; it is also linked publicly. | Two places to update on every rule change (and I forgot once). | S: keep it as a developer page, unlinked. |
| P2 | `legacy.ts` and the old-route table must live until old saves stop mattering. | Dead weight. | S: put a removal date in `CLAUDE.md`. |
| P2 | Dictionaries are edited by hand in six files; non-Turkish text has had no native review. | Wrong or stiff wording in de/fr/es/it/pt. | M: ask native speakers or a translation service before launch. |
| P2 | No `LICENSE`, no `CONTRIBUTING.md` (the goal was to let foreign developers join); `.gitignore` still lists `.vercel`. | Contributors do not know the terms. | S |
| P2 | CSS uses `:has()` and `color-mix()`. | Needs iOS 16.2+ / a current Android WebView. | S: set the minimum OS in the store build. |

## 2. Gamer

| Pri | Item | Why | Size |
|---|---|---|---|
| P0 | **The first tap on "Start" opens a setup sheet** (players, board size, difficulty, bots, options). *Checked.* | New players decide before they understand anything. | S: one "Quick match" button with the best defaults; keep the sheet as "Custom". |
| P1 | **Difficulty jump.** A careful player wins 92% on Easy, ~37% on Normal, ~15% on Hard (engine test). | Casual players hit a wall after Easy. | M: a gentler step (or adaptive help after two losses); consider showing "Easy / Normal / Hard" win odds. |
| P1 | **No social loop**: no friends, no daily leaderboard, no challenge-a-friend link, no emotes. Online rooms are phone-to-phone with a code. | Retention in this genre comes from beating people you know. | L (a daily board needs a small server). |
| P1 | **Feedback on iPhone.** Vibration uses `navigator.vibrate`, which iOS does not support. *Checked in code.* Sounds are synthesized and the silent switch mutes them; there is no menu music. | The "feel" work (haptics, slash, bonus sounds) is invisible on iOS. | M: native haptics in the Capacitor build; consider a few recorded sounds and a menu loop. |
| P2 | Switcheroo (swap with any piece, and the AI uses it) may be too strong. | Balance. *Judged.* | S: simulate bonus-on vs bonus-off win rates; the engine test file already has the harness. |
| P2 | Goals beyond cosmetics: achievements, a weekly challenge, a "win without a bonus" style. | More reasons to return. | M |
| P2 | After you are out in a 4-player match you can only watch at normal speed. | Long dead time. | S: let the spectator speed up bot turns. |

## 3. Everyday user and accessibility

| Pri | Item | Why | Size |
|---|---|---|---|
| P1 | **Small touch targets.** The bonus guide button is 24 px (the standard is 44). *Checked.* | Hard to hit; it is the way into the guide. | S: bigger hit area without a bigger icon. |
| P1 | **Fonts come from Google Fonts.** *Checked in `app/index.html`.* | Sends every player's IP to Google (a privacy-policy and GDPR matter), fails offline, slows first paint. | S: self-host Oxanium and Barlow (both OFL). |
| P1 | Several captions are 10.5–12 px; there is no text-size setting. | Hard to read for many players. | M |
| P2 | No offline play on the web (no service worker), although the app is installable. | Single-player does not need a network. | S |
| P2 | Only 7 languages; no Arabic, Russian, Japanese, Korean, Hindi, Indonesian; no right-to-left layout. | Store reach. *Judged.* | L |
| P2 | Screen-reader support is partial: the board is a labelled grid and turns are announced, but the new bonus strip and guide were not checked with VoiceOver or TalkBack. | Accessibility. | M |

| P1 | **Invite links have no preview.** *Checked:* no Open Graph tags or share image in `app/index.html`. | A WhatsApp link shows a bare URL, the main way rooms are shared. | S |

## 5. What to cut or hide

- The public `/arena/` page and the raw `/engine/` files on the site: players land on them by accident. Keep them in the repo, stop linking them.
- `.vercel` in `.gitignore` (a leftover from the removed Vercel project).
- Do not add more rewards before the billing decision (section 4).

## 6. Suggested order

1. Rules version + desync check, error boundary, "Quick match" button. (P0, one session.)
2. Self-host fonts, bigger touch targets, share preview tags, `LICENSE`, `CONTRIBUTING.md`, privacy-policy page. (Small, one session.)
3. Capacitor shell with native haptics and Game Center / Play Games. (Needs the accounts.)
4. Decide TURN versus an own server, and the billing approach, before any marketing.
5. Smoke tests in CI, split `controller.ts`, difficulty step, native-speaker review.
